# Stagecoach as a Paper plugin — handoff

For whoever works on Stagecoach next. You know the mod; this explains what changed to make it a **Paper 1.21.11
plugin** that still looks and feels like the mod, with players on a plain vanilla client.

This is the short version: what it is, how the look was kept, what bit us, and how to work on it.

---

## What it is

- **Where:** `minecraftmodding/mods/Stagecoach-plugin/` — its own codebase (package `net.feelix.stagecoach.bukkit`),
  Java 21, Gradle 9.5.1, `compileOnly paper-api 1.21.11-R0.1-SNAPSHOT`.
- **Runs on:** Paper or Purpur 1.21.11. **Not Spigot** — it uses Paper's dialog screens and Paper's join-time
  resource-pack event. On Spigot it logs why and disables itself.
- **Build:** `./gradlew build` → `build/libs/`:
  - `Stagecoach-paper-1.21.11-1.1.0.jar` — the plugin (its resource pack is inside).
  - `Stagecoach-pack-merger-1.1.0.jar` — a standalone tool for server owners (see below).
  - `Stagecoach-resourcepack-1.21.11-1.1.0.zip` — the resource pack on its own (the exact zip the plugin serves).
- **Status:** 1.1.0 (its first release; 1.0.0 was never uploaded), **not uploaded**. It needs its own CurseForge project: Bukkit plugins are a separate project
  class and can't be files on the mod's project. `docs/release/CURSEFORGE.md` has every form field.

Same rules as the mod, ported line by line: the fare (XP or items), travel time, names, the reach, combat lock,
discovery, owner-only breaking, safe landing spots, and the **crash-safety order** in `travel/JourneyManager`. Since
1.1.0 the mod's server settings exist here under the same names (`config.yml`).

## How it still looks like the mod (the tricks)

A vanilla client can only draw what a resource pack gives it. So the plugin **generates a resource pack from the
mod's own assets and serves it itself**.

### 1. The coach is the mod's real model, as 99 item displays
- The GeckoLib model has 99 cubes. Each becomes an **item display** wearing a pack model
  (`stagecoach:coach/<wood>/<i>`). That model is a plain 16px cube whose six faces carry that cube's UVs from the
  mod's texture.
- Each display gets a transformation matrix that squeezes and turns the cube into place. `tools/generate_model.py`
  computes the matrices by importing the mod's own `generate_footprint.py`, which replays GeckoLib 4.8.4's transform
  chain. So the shape matches the mod's collision footprint exactly.
- ⚠ The client draws an item display's model **turned 180° about Y and shifted −0.5 on every axis** (read in the
  1.21.11 client code). `CoachModel.displayMatrix` undoes both. Change that and every piece flips.
- Result: the coach in the world is pixel-for-pixel the mod's coach, in all 11 woods.

### 2. Collision = barrier blocks
- 28 of the 45 footprint cells get an invisible barrier (cells that are at least 4% model). The other 17 (railing
  tips, shaft tip) stay air, and the plugin keeps blocks, water, pistons and growing trees out of them.
- Barriers make the coach TNT-, piston- and water-proof for free.
- Placing asks protection plugins: each cell is set to a barrier and announced with a real `BlockPlaceEvent`. If
  anything cancels one, every cell is reverted.

### 3. The mod's three screens are Paper dialogs
- **Naming:** a text box with the coach icon.
- **Destination list:** a search box, one button per stop (name, time, cost; tooltip with the details), Rename, Close.
  A stop opens "Travel to X?" → Set off / Back.
- **Travel screen:** the **road scene is a picture inside the dialog**. `tools/generate_pack.py` ports the mod's
  `RoadScene` + `Landscape` to Python and renders 24 frames (192×108, 16px of road apart) into a **font glyph**.
  The plugin re-shows the dialog every 10 ticks with the next frame — the same 1.6 px/tick scroll as the mod. Below it
  are a hay-filled progress bar (glyphs), "m:ss remaining", and **Cancel journey** → "Abandon journey?".

### 4. The placement ghost
- The same 99 pieces as item displays wearing tinted, 45%-transparent textures (the mod's green and red), plus a red
  box per blocked cell.
- **Only the holder sees it** (`setVisibleByDefault(false)` + `showEntity`).

### 5. Item icons
- Each wood's item is an oak chest boat underneath, with `item_model` pointing at a 64px icon rendered from the mod's
  model by the mod's own `render_icon.py`.
- The boat's vanilla uses (placing, dispensing, burning, crafting) are all blocked.

## The resource pack

- **Source:** `pack/`, generated by `python tools/generate_pack.py`. It's committed; regenerate it after the mod's
  model or textures change. About 1.7 MB, 2,628 files, pack format 75. Everything lives in the `stagecoach`
  namespace, so it never overwrites anyone's pack.
- **Build:** Gradle zips it reproducibly into the jar (stable SHA-1, so clients cache it).
- **Delivery:** the plugin serves the zip on **port 8163** and offers it in Paper's configuration phase
  (`AsyncPlayerConnectionConfigureEvent`), while the player is still on the joining screen. It waits for their
  answer. With `required: true` (the default), a player who doesn't accept or can't download is **disconnected with a
  reason**, rather than joining with every coach showing as a missing model.
- **Config** (`resourcePack.*`):

  | Setting | What it does |
  |---|---|
  | `send` | `false` if the server's own pack already carries Stagecoach |
  | `required` | Players must accept the pack to join |
  | `port` | Where the plugin serves the pack (8163) |
  | `host` | Public address; blank = the address each player joined with |
  | `url` | A link to a self-hosted copy of the zip, for hosts that can't open a port |

- **Pack Merger** (the second jar): for servers that ship their own resource pack. Double-click, pick the pack, and
  it writes "<pack> + Stagecoach.zip":
  - Their files and `pack.mcmeta` are kept; `assets/stagecoach/` is replaced wholesale, so re-running it after an
    update updates Stagecoach.
  - It prints the SHA-1 for `server.properties` and warns if their `pack.mcmeta` doesn't cover 1.21.11.
  - It also has a command-line mode.
- **Licence:** a clause was added allowing server owners to add the pack, unchanged, to their own server pack
  (without it, the merger would break our own terms).

## Things that bit us (read before changing the matching code)

1. **Dialogs must use `afterAction NONE`.** With `WAIT_FOR_RESPONSE` the client shows a "Waiting for Server" screen
   after a click, and the client's "close dialog" never closes that screen. Confirm, Close and Esc left players stuck.
   Now every click is answered by showing the next dialog or closing.
2. **Paper refuses a multi-action dialog with no buttons.** A visitor's first stop has nothing to list and no Rename,
   so the empty list is a notice with a Close button (found by the bot tests).
3. **The ghost only spawns once the client has its chunk** (`player.isChunkSent`). It's re-created, not teleported,
   after a jump of more than 16 blocks. A display that appears in a chunk still on its way to the client is never
   shown later: displays never move on their own, and the server only re-offers entities that change section.
4. **The travel picture has to stay small.** At 1080p with GUI scale 4 there are only ~270 GUI pixels of height. A
   bigger picture pushes the bar and countdown below a scrollbar.
5. **Font glyphs are capped at 256×256** (one font texture page). That's why the road picture is 192×108.
6. **Paper vs Spigot:** Paper hard-forked from Spigot, so newer Spigot API isn't guaranteed on Paper. This build is
   Paper-only on purpose.
7. **Bots (mineflayer) can't click dialogs or take a resource pack** during the join. The screens are tested with the
   real client (below).

## Testing

| What | Command (from the plugin root) | Result |
|---|---|---|
| Unit tests | `./gradlew build` | **25 JUnit**: rules (incl. item cost, route limit, partial refunds), config incl. the 1.1.0 settings, old journey records, messages (every key exists), model = mod's model, footprint in all four facings, network file, pack merger |
| World rules with bots | `tools/e2e/e2e.js <server dir> <jar> 25590 25591` | **15/15**: placing, refusals (another coach, a mob, protected land via a stand-in protection plugin), discovery, owner-only breaking, water/pistons/TNT, take-down, dispenser, display repair, clean log |
| Crash safety with the real client | `tools/e2e/journeys.js <server dir> <jar> 25591` | **4/4**: a journey started from the screens pays; quitting, `/stop` and a hard server kill mid-journey each restore the player (checked in the saved player file) |
| The look | `tools/e2e/shots.js 25591` + `devclient ./gradlew runHarness` | Screenshots of every screen: ghost, naming, coach, list, confirm, travel, abandon, arrival |

- **Dev client** (`devclient/`, an empty Fabric Loom 1.21.11 project):
  - `./gradlew runClient` — joins the test server as a normal player.
  - `./gradlew runHarness` — the test client. Its window is **invisible and muted**, it screenshots every screen,
    follows `#command` chat lines from the server (click, type, use, look, shot, quit), and quits when disconnected.
    ⚠ Don't run it while someone is gaming on the same PC.
- **Test server:** `minecraftmodding/server/paper-1.21.11-test-server/`
  - Paper build 132. Game port 25590, RCON 25591 (password `stagecoach`), pack port 8163.
  - Offline mode, flat world, new players join in creative.

## Working on it

| To… | Do |
|---|---|
| Change the mod's model or textures | Regenerate the mod's footprint first, then `python tools/generate_model.py` and `python tools/generate_pack.py`, then rebuild. `CoachModelTest` fails while the model SHA-1 is stale |
| Change a message | Edit `messages.yml` (players can edit their copy too). A test checks every key the code uses exists |
| Change the travel picture | Edit `road_frame` in `generate_pack.py`; keep it ≤ 256px and short enough to fit (see "Things that bit us" 4) |
| Add a wood | Add it to `Wood.java` and to `WOODS` in `generate_pack.py`; the mod needs its texture |

## Not done yet / worth knowing

- Nothing is uploaded; the CurseForge project doesn't exist yet.
- In-game screenshots for the store page haven't been taken (the gallery has renders).
- Only tested on Paper build 132. Purpur, Folia (not supported: it uses the normal scheduler), 26.x and online-mode
  servers haven't been tried.
- Land protection was proven with a stand-in plugin, not WorldGuard or GriefPrevention themselves.
- The Pack Merger's **window** hasn't been opened in a test; its merge logic and command line are covered by tests.
- The "chat can't be verified" triangle in the screenshots is from the offline-mode test server, not the plugin.
