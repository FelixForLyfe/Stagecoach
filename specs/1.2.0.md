# Stagecoach 1.2.0 — pack developer features

Source: `stagecoach-packdev-spec.md` (2026-10-13). Every section of it ships in 1.2.0 on all fourteen builds. This
file records how each part maps onto the existing code and every place the build differs from the spec. All 61
proposals were locked on 2026-10-13; Feelix changed #53 on 2026-10-14.

## Facts from the code (spec §0.1)

| Question | Answer |
|---|---|
| Mod id, package | `stagecoach`, `net.feelix.stagecoach` |
| Block or entity | Block multiblock: a controller block with a block entity (holds the stop id) plus 44 invisible part blocks |
| Where stops live | One saved-data file on the overworld, `stagecoach_network.dat`, every dimension in it |
| Multi-loader | One codebase per Minecraft version; `common/` is compiled into each loader project; a thin layer per loader |
| Unique names | No |
| Command tree | `/stagecoach` (level 2) with `reload` only |

## Proposals

### Stop data
1. ⚠ **Stop ids stay numeric.** The existing id (a long, never reused, stored in the coach's block entity) is the one
   stable id. Commands accept `#12`, the API uses `long`. No UUID is added (it would be a second id for the same
   thing). (alt: add a UUID beside it)
2. New fields on each stop: `public`, `hidden`, `locked`, `free`, `costMultiplier`, `scene`, `createdBy`, and `wood`
   (the variant, for `StopView` and export). The state file gets `dataVersion: 2`; a file without it is version 1 and
   loads with every new field at its default. 1.1.0's coaches with no owner (dispenser-placed) become ownerless stops.
3. `hidden` stops are left out of every destination list, the owner's too, but can still be departed from.
4. `public` stops count as discovered for everyone; right-clicking one opens the list straight away.
5. `locked`: the break event refuses everyone (ops in creative too), explosions skip it (a mixin on vanilla's
   explosion block check), pistons and fluids already can't touch a coach. `/setblock` and `/fill` still can;
   documented. `stop remove` works on locked stops.
6. Coaches made by `stop create`, `import` or a structure never drop the coach item when broken; only player-placed
   ones do. (The spec says this for generated coaches only; the others are free items too.)

### Commands
7. Admin subcommands need `adminCommandLevel` (or `stagecoach.admin.commands`); players without it see none of them.
8. `<stop>` is a name (quoted when it has spaces, case-insensitive exact match) or `#<id>`. Two matches: an error
   listing each with its id and position. Tab completion offers names and ids.
9. `stop create <name> [pos] [facing] [wood] [force]`: `<name>` is a quoted string. Facing defaults to the
   executor's horizontal facing (north from a command block). Without `force` it runs the normal clearance check and
   the blocked-dimension check; with `force` it replaces blocks in the way and ignores both.
10. `stop list [dimension] [page]`: 10 per page, each line clickable (runs `stop info #id`), clickable previous/next.
11. `stop setowner <stop> <player|none>` takes a player name (online or in the server's name cache).
12. `stop remove <stop> keepCoach` marks the coach as decoration in its block entity: it never registers again and
    right-clicking it says it's out of service.
13. `journey send` starts from where each target stands: cancelling, a refund or crash recovery returns them to that
    spot. Without `free` they pay the normal fare for that distance; a target who can't pay, is already travelling,
    is a spectator or is dead is skipped with a line saying why.
14. `/stagecoach reload` re-reads the config and re-applies structure injections from the loaded files. Datapack
    files (travel rules, themes, name pools, injections) reload with `/reload`, resource-pack scenes with F3+T, as
    vanilla data does; the command says so.
15. `discover`/`forget` with `*` means every stop. Owners always know their own coaches, so forgetting can't hide one
    from its owner.

### Structures
16. A coach's block entity is queued when it joins a loaded world (chunk load, structure, command) and checked on the
    next server tick, never by scanning. An absent or unknown id, or an id registered somewhere else, makes a new
    ownerless STRUCTURE stop; the template keys are applied and then removed; the parts are laid again around the
    controller so rotated and mirrored templates come out whole. (Mirroring is also fixed for the blocks themselves.)
17. ⚠ 1.1.0 change: a controller placed with `/setblock` becomes an ownerless stop with its parts at once, instead
    of being claimed by whoever right-clicks it first.
18. `autoNameFormat` fills `{biome}` with the biome's English name from the server's language, else from its id
    ("cherry_grove" → "Cherry Grove"). Stop names are stored text, so they aren't translated. The " (2)" suffix
    applies to automatic and template names only, never to names players type.

### Recipes, tags
19. Recipe ids are already `stagecoach:<wood>_stagecoach` and `stagecoach:tfc/<wood>_stagecoach`. The unlock
    advancement keeps vanilla's own layout, `stagecoach:recipes/transportation/<wood>_stagecoach`. (alt: move to
    the spec's `stagecoach:recipes/<wood>_stagecoach`)
20. Block tag `stagecoach:stagecoaches` holds the eleven controllers and the part block. `placement_blocked_on` is
    checked against the block under each bottom cell. No `c:` tag fits a coach, so none is added.

### Advancements, stats
21. The five triggers and conditions as specified; `stop_id` is the number, `cost` is what was paid (levels or items).
22. Built-in tab "Stagecoach": *On the Road* (place a coach, root), *Fare Paid* (finish a journey), *Well
    Travelled* (know 10 stops), *The Long Road* (one journey of 10,000+ blocks). Behind `builtinAdvancements` through
    each loader's load condition. Recipe unlocks are not part of the tab and not affected.
23. Blocks travelled is added on arrival: the straight distance, or `crossDimensionDistance` across dimensions.

### API, events
24. `net.feelix.stagecoach.api` (`StagecoachAPI`, `StopView`, `JourneyOptions`, `JourneyResult`, `CreatedBy`,
    `EndReason`, `Destination`) and `net.feelix.stagecoach.api.event`. The same class names and methods on every
    loader: Forge and NeoForge post them on their event bus, Fabric has a static `EVENT` on each event class.
    `API_VERSION = 1`. Parameter types follow each build's mappings.
25. No separate `-api` jar: the API is inside the mod jar; the docs give the Curse Maven coordinate and the GitHub
    release jars for `compileOnly`.
26. `JourneyEnded` reasons: the spec's five plus `DESTINATION_GONE`, `GAME_MODE_CHANGED`, `DIED`, `RECOVERED`
    (refunded at login after a crash). A journey recovered at login in its arriving phase counts as `COMPLETED`.
    Instant travel fires started, completed and ended in a row.
27. `JourneyPreStart` fires after every built-in check (travel rules too) and before payment, for player journeys,
    `journey send` and API starts. Changing its cost is not reflected in the list; a listener that changes fares
    should change the `DestinationList` entry as well (documented).
28. `StopDiscover` fires for right-click discovery and `/stagecoach discover`, not for the API's `discover()`.
    `CoachPlace` fires for player placement, `stop create` and `import`; `CoachBreak` for a player breaking one.
29. `DestinationList` holds `Destination` entries (stop, cost, seconds, status, lock message) in a mutable list:
    add, remove, reorder or replace. The server rebuilds the list for a travel request, so only an entry with status
    OK in that final list can be travelled to.
30. KubeJS: `ForgeEvents.onEvent` examples on Forge 1.20.1 in the docs; the native plugin
    (`StagecoachEvents.*` + a `Stagecoach` binding) on every build that has a KubeJS release.

### Cost
31. Fare: base → × stop `costMultiplier` → × dimension multiplier → × cross-dimension multiplier → × travel-rule
    multipliers → round up → clamp → 0 for a free stop, creative or `stagecoach.bypass.cost` → `JourneyPreStart`.
    The list and the charge come from one function. Across dimensions `crossDimensionDistance` replaces the distance
    for cost, time and `maxDistance`.

### Travel rules
32. As specified. `item` means anywhere in the inventory (armour and off hand too), not taken. `permission` is any
    node. `stage` (GameStages) only on builds where GameStages exists. A failing rule shows the destination greyed
    with `deny_message` as its tooltip and the server refuses it. One error line per bad file (path and reason).

### Theming
33. ⚠ **The built-in road stays the procedural scene.** `stagecoach:road` is a scene file saying
    `"builtin": "road"`; a pack replaces it by overriding that file with layers. Broken scenes fall back to the
    built-in road. (Rewriting the road as image layers would change how it looks.)
34. Layer fields: `texture`, `speed` (× the road's 1.6 GUI px per tick), `y` (top edge, fraction of the height), and
    two additions: `scale` (GUI px per texture px, default 1) and `fill` (a colour drawn from the layer's bottom to
    the screen's bottom). `coach` shows the walking traveller on the progress bar. `ambient_sound` loops while the
    screen is open.
35. Scene choice: `scene_rules.json` lives in resource packs, which the server can't read, so the server sends the
    stop's scene, its `defaultScene`, the destination biome and dimension, and the client picks: stop scene → its
    own rules (biome tag or dimension, first match; files from every namespace) → server default → road. Scenes only
    change the road style; the map and minimal styles stay as they are.
36. `forceClientTravelStyle` reaches clients when they join and after `/stagecoach reload`; the config screen greys
    the two style rows with a tooltip.
37. Sounds: `journey.arrive` = the bell 1.1.0 plays (the horse breath stays a vanilla sound beside it);
    `journey.depart` = a horse gallop (new); `journey.loop` = empty until Feelix supplies one (played only when it has
    a sound, so no log warnings). (alt: depart silent too)
38. Config warnings shown by `/stagecoach reload` stay English (they're the same lines as the server log).

### Permissions
39. Nodes and defaults as specified; Forge and NeoForge register them with `PermissionAPI`; Fabric uses
    fabric-permissions-api only when a mod has installed it. `stagecoach.admin.manage` defaults to op level 2 while
    `opsCanManageAnyCoach` is on, nobody when it's off.

### Compat
40. Open Parties and Claims: the same per-cell claim check as FTB Chunks, on builds where OPAC exists.
41. Waypoints: the client gets the list of stops it knows (on join and when it changes) and adds a "Stagecoach" set
    to JourneyMap (public API) and Xaero's minimap (no public API: its internal classes, guarded so an Xaero update
    can only switch the feature off, never crash). Only on builds where those mods exist. (alt: JourneyMap only)
42. FTB Quests: documentation only (advancement tasks).

### Export, import
43. `export <name>` / `import <name> [replace]` as specified. Import force-loads each chunk briefly and places with
    `force`. Without `replace` a stop is skipped when one with the same name or position exists; with `replace` that
    stop is removed first.

### Performance
44. Stops indexed by dimension and by chunk; the tick returns at once when nobody travels; rules and events run only
    when a list opens or a journey starts. A GameTest builds a list over 500 stops for 50 players and records the
    time.
45. The destination list goes out in pages of 200 entries, all sent together; the screen fills in as they arrive and
    search covers everything received.

### Discovery and placement feedback
46. The discovery card is a vanilla toast (top right, slides in and out) styled as a wooden road sign, 3 s. (alt: a
    custom HUD card at the top centre, which needs a separate HUD hook per loader and version)
47. Embers rise from the tops of the four corner pillars (the model has no lanterns).
48. The placement effect plays when the coach is placed (before naming): the sound at the coach for nearby players
    (`coach.place` placeholder = the horse saddle sound; the planks' own place sound already plays), and a small
    packet to nearby players whose client spawns the dust if `placementEffects` is on.
49. Placeholder particle textures are drawn in Aseprite; Feelix replaces them.

### Natural generation
50. ⚠ The theme reaches the coach through a custom structure processor `stagecoach:coach_stop` on each injected
    piece. It writes the theme into the coach's template data and swaps the piece's oak decor to the theme's
    `decor_palette` wood (any `minecraft:oak_<x>` block whose `<palette>_<x>` exists). One template serves every
    theme, as the spec wants; vanilla rule processors can't do this because they reset the coach's facing.
51. The placeholder piece `stagecoach:village/coach_stop_small` (dirt path, hitching post, lantern on a post, a sign
    post) with a jigsaw that matches the village house connectors of each target, checked in each mod's own files.
52. The one-stop-per-settlement cap applies to themed coaches only, so a pack's own town template with three coaches
    keeps all three.
53. **Changed by Feelix on 2026-10-14: with natural generation on, EVERY village gets a coach stop, in the wood the
    village is built from.** (This replaced "weights tuned so about half to most villages get one".) How:
    - The pools are never edited. A mixin on the jigsaw assembler adds the coach-stop pieces to the list a slot is
      about to try, first in line until the village has a stop, then never again (`maxGeneratedStopsPerStructure`).
      Reason, measured on a real server: with the pieces added to the pools by weight, 0 of 150 vanilla villages got a
      stop, because Lithostitched (CTOV's library) rebuilds every template pool after Stagecoach edits them. Without
      it, 8 of 8. Offering at assembly time can't be undone by any pool rewriter.
    - Three shapes are offered, in order: the coach facing the street (7 x 8), parked alongside it (8 x 5), and the
      coach alone beside the road (6 x 4) for the tightest plots. With only the first, 1 desert village in 12 got none;
      with two, a few Towns and Towers villages still missed out.
    - Each injection names its village's wood (`"wood"`), counted from the houses in that village's own templates
      (`tools/count_village_woods.py`): plains oak, desert jungle, savanna acacia, snowy and taiga spruce, and so on.
      Zombie villages share their living village's file.
    - Injections are `"guaranteed": true` by default; `"guaranteed": false` plus `weight` keeps the old chance (the
      Dungeons and Taverns taverns use it: they aren't villages, and a guaranteed stop would take every tavern's event
      slot). `generationWeightMultiplier` now scales only those.
    - Every jigsaw assembler is hooked: vanilla's, Lithostitched's (both its 1.x package and 2.x's `impl` package, one
      mixin each, added only when that class exists — a single mixin naming both targets is dropped by Mixin when one is
      missing), Repurposed Structures' and Integrated API's.
    - Measured: GameTest `everyVanillaVillageGetsExactlyOneStop` assembles 20 villages of each vanilla type on every
      build, 100 of 100 have exactly one. On real servers with every structure mod, on the final jars: 1.20.1 Fabric 288 of
      288 villages and Forge 93 of 93 (Integrated Villages included); 26.3 Fabric every village type with streets 100%
      (vanilla 40/40, Repurposed Structures 45/45, Towns and Towers 62/62, Dungeons and Taverns villages 18/18);
      taverns by chance (49 and 51 of 55 in two 1.20.1 runs). Count a stop about 2 s after placing: at 0.4 s under load
      a late registration reads as a miss.
54. Injection files (94, the same in every folder; a pool a version doesn't have is skipped at runtime): the five
    vanilla villages, Repurposed Structures (16), CTOV (21), Towns and Towers (23 house pools), Integrated Villages
    (11) and Dungeons and Taverns (5 villages, joined by their own connector names, plus 13 taverns). Pool ids were
    read from each mod's jar for every Minecraft version. Not covered: Towns and Towers' grove outpost, snowy-slopes
    inn and savanna-plateau tower (one building, no street) and nilotic village (houses stack onto a base plate) —
    each would need a purpose-built piece. Moog's Voyager Structures has no villages (single buildings and camps only,
    checked in its 1.20.1 jar), so it gets no file.
55. Name pools: about 20 prefixes × 15 suffixes × 3 patterns each, checked by a JUnit test (200+ combinations, length,
    a blocklist of place names from games, books and shows, and a bad-word list).

    1.21.1, 1.21.11, 26.2 and 26.3 one version at a time. (The spec ports every phase before starting the next; the
    result is the same jars with fewer passes.)

    the Linen check. (alt: port the server-side parts to it)

59. One combined changelog grouped by phase, plus one per uploaded file; the CurseForge description updated for
    natural generation.
60. The spec's wiki becomes the GitHub Pages site: a pack developer guide and a modder guide, with the spec's twelve

61. The Linen check covers the five mod folders, the Paper plugin and its dev client, and the Python tools. Not
